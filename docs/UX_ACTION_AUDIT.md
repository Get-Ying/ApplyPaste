# ApplyPaste 操作语义审计

## 当前信息层级

当前 ApplyPaste 的用户可见信息层级可以解释为：

```text
分类
↓
条目 / 卡片
↓
字段
```

实际代码中：

- 分类来自 `profile.categories`。
- 条目 / 卡片来自 `profile.items`，每个条目包含 `category`、`title`、`tags`、`content` 和可选 `fields`。
- 字段来自条目的 `fields`，字段有 `label`、`value`、`versioned`，岗位版本通过 `version.fieldOverrides[field.id]` 保存差异。
- 附件与投递记录是独立列表，附件可绑定填写版本，投递记录独立保存。

本轮没有修改数据模型、IndexedDB schema、版本存储、投递记录逻辑、飞书同步或 Word 解析。

## P0 / P1 / P2

### P0

- 未发现会直接导致误删、误改或覆盖错误数据的 P0。版本编辑弹窗已有“当前版本差异 / 通用答案”提示，事实字段修改也已有确认。

### P1

- 顶层“新增”目标不明确，已改为“添加条目”。
- 卡片级“+ 字段”目标不明确，已改为“+ 添加字段”。
- 卡片级“复制”与“复制全部”同时出现，已改为“复制条目”。
- 卡片级“编辑”对象不够明确，已改为“编辑条目”。
- 危险操作“删除”在条目、字段、分类、附件按钮上对象不够明确，已分别改为“删除条目 / 删除字段 / 删除分类 / 删除附件”。
- “使用通用答案”可能被理解为普通粘贴/覆盖，已改为“恢复使用通用答案”并补充 title。

### P2

- 附件区“+ 附件”可以改为“+ 添加附件”，但对象已经清楚，本轮未改。
- 投递流程里的“保存并同步”在未启用飞书时实际只保存本地并提示未配置，属于后续文案优化，不属于本轮 CRUD 语义高风险问题。

## 场景复核

- 新增一个项目：当前分类为“项目经历”时，入口显示“添加条目”，弹窗标题为“新增条目”，默认标题为“新项目经历”，无需猜是新增字段。
- 给现有项目增加“项目成果”：卡片内入口显示“+ 添加字段”，字段弹窗标题为“新增字段”，对象是当前条目。
- 修改手机号：字段行右侧“编辑”紧贴手机号字段，字段弹窗标题为“编辑字段”。
- 删除一个项目：条目弹窗按钮为“删除条目”，确认文案明确删除条目及其字段差异。
- 岗位版本修改项目描述：字段编辑提示会说明“保存后只更新当前岗位版本差异”或“内容将保存为当前版本差异”。
- 点击复制：字段值点击只复制字段值；卡片按钮为“复制全部 / 复制内容”；复制卡片副本按钮为“复制条目”。
